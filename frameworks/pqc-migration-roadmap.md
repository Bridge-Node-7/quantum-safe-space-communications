# Post-Quantum Migration Roadmap

## Phase 0. Authority and scope

Establish sponsor, owner, approved boundaries, information-handling rules, and decision authority.

## Phase 1. Inventory and visibility

Map links, assets, protocols, implementations, keys, certificates, signing, secure boot, vendors, and update paths.

## Phase 2. Exposure and prioritization

Record per-item Quantum Exposure Severity, data horizons, mission consequences, unknowns, and critical overrides.

## Phase 3. Target architecture

Define algorithm and protocol transition criteria, crypto-agility, key and trust management, downgrade prevention, recovery, and vendor dependencies.

## Phase 4. Representative pilots

Test performance, interoperability, frame overhead, latency, SWaP, update, rollback, recovery, and operational procedures.

## Phase 5. Governed deployment

Deploy through controlled change with evidence, configuration management, acceptance criteria, and rollback.

## Phase 6. Legacy exit

Remove obsolete paths, dual-stack modes, unsupported dependencies, stale trust anchors, and temporary exceptions according to approved exit criteria.

## Phase 7. Sustainment and reassessment

Monitor standards, implementation vulnerabilities, vendor status, evidence freshness, control performance, recovery readiness, and mission changes.

## Required roadmap fields

- Transition profile by system and link
- Algorithm and protocol selection criteria
- Performance and hardware constraints
- Hybrid transition rationale where used
- Interoperability evidence
- Vendor milestones
- Key and trust transition
- Secure update and rollback
- Dual-stack exit criteria
- Legacy decommissioning
- Emergency recovery
- Reassessment triggers
